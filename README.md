# DANI Planner — راهنمای تو (کاربر)

پلنر شخصی فارسی؛ بدون سرور؛ داده فقط داخل مرورگر/اپ خودت. قاعده‌های هوش مصنوعی در `AI.md` است.

## ۱) با هر هوش مصنوعی چه بفرستم؟ (همیشه همین سه چیز)
1. فایل **`AI.md`** (قاعده‌ها، کم‌حجم‌ترین ساخت، شکل تحویل، نقشه‌ی کد، هماهنگی بین چند هوش مصنوعی).
2. **zip تازه‌ی مخزن** (Code ← Download ZIP)، یا فقط فایل‌های همان بخش (جدول پایین).
3. این متن (کار را جای نقطه‌ها بنویس):
```
پروژه‌ی DANI Planner. AI.md پیوست است؛ کامل بخوان و همه‌ی قاعده‌هایش (به‌ویژه کم‌حجم‌ترین ساخت، تحویل و هماهنگی) را بدون پرسیدن رعایت کن.
هیچ قابلیتی حذف نشود. فقط یک کار: …
```
بعد از آن، هوش مصنوعی خودش می‌پرسد «از آخرین زیپ چیزی عوض شده؟» و فهرست دقیق «جایگزین/اضافه/حذف» را می‌دهد.

## ۳) آپلود در GitHub (با گوشی)
1. وارد پوشه‌ی درست شو (مثلاً `js`) ← Add file ← Upload files ← فایل را بکش. نام تکراری، فایل قبلی را جایگزین می‌کند؛ پس نام **بدون `-1` یا `(1)`** باشد، وگرنه کپی سرگردان می‌ماند.
2. با zip: باز کن و **پوشه‌ها و فایل‌های داخلش** را با هم بکش؛ فقط همان فایل‌ها عوض می‌شوند.
3. فایل‌هایی که هوش مصنوعی در «حذف کن» نوشته را در GitHub باز کن ← سه‌نقطه ← Delete file.
4. فایل داخل پوشه‌ی مخفی `.github/…` راحت‌تر این‌طور: Add file ← Create new file ← نام کامل مسیر را بنویس ← محتوا را جایگذاری کن.
5. Commit changes ← ۲ دقیقه صبر ← سایت را رفرش کن (یا اپ را ببند و باز کن).
6. بعد از آپلود چند صفحه را نگاه کن؛ اگر خراب بود، فایل‌های قبلی را دوباره آپلود کن.
7. مقایسه‌ی zip قدیمی و جدید (بدون Python): `tools/zip-compare.html` را در مرورگر باز کن.

## ۴) اپ اندروید
- اپ فقط یک «پوسته» است که سایت GitHub Pages را باز می‌کند؛ پس هر آپلود (Commit) چند دقیقه بعد در اپ هم می‌آید. **APK جدید فقط وقتی لازم است** که چیزی در `android-shell/`، صدای اعلان، آیکون، مجوز یا افزونه‌ی اندروید عوض شده باشد؛ هوش مصنوعی باید این را صریح بگوید.
- **ساخت:** مخزن ← Actions ← Build Android app ← Run workflow (حالت `live`) ← ۷ تا ۱۲ دقیقه ← Releases ← `android-latest` ← `DANI-Planner.apk` را دانلود و نصب کن. اگر قرمز شد، چند خط آخر خطا را برای هوش مصنوعی بفرست.
- **بعد از نصب:** تنظیمات ← زمان و اعلان ← «درخواست اجازه‌ی اعلان» و (اگر بود) «آلارم دقیق»؛ «زنگ آزمایشی (۱۰ ثانیه)» را بزن، اپ را ببند و صفحه را قفل کن. اگر زنگ دیر آمد: تنظیمات گوشی ← برنامه‌ها ← DANI ← باتری ← «بدون محدودیت».
- **ذخیره‌ی پشتیبان در اپ:** دکمه‌ی دانلود/پشتیبان حالا پنجره‌ی اشتراک‌گذاری اندروید را باز می‌کند؛ «ذخیره در Files/Drive» یا «تلگرام ← Saved Messages» را انتخاب کن. (این قابلیت فقط با APK ساخته‌شده بعد از افزودن `native-save.js` کار می‌کند.)
- **انتقال داده:** اپ و مرورگر حافظه‌ی جدا دارند. در مرورگر قدیمی: تنظیمات ← داده ← پشتیبان کامل؛ داخل اپ: همان‌جا بازیابی. داده‌ی تو داخل مرورگر/اپ است، نه GitHub؛ آپلود فایل داده‌ات را عوض نمی‌کند.
- **چه چیزهایی خودکار زمان‌بندی می‌شوند؟** پایان تایمر شمارش‌معکوس (زنگ بلند حدود ۳۳ ثانیه)، هشدار چند دقیقه مانده به پایان، و یادآورها/موعدهای ۱۴ روز آینده (با رعایت «ساعت سکوت»). با هر تغییر و هر بار بسته‌شدن برنامه دوباره ثبت می‌شوند. کرنومتر زنگ ندارد.
- **محدودیت‌های صادقانه:** اپ از نوع «debug» است و با کلید آزمایشی امضا می‌شود (برای استفاده‌ی شخصی کافی است). نسخه‌ی iPhone ندارد. اگر روزی خواستی اپ بدون اینترنت از اول باز شود: Run workflow با حالت `bundled`.
- حالت `bundled` (بدون اینترنت از اول) برای هر به‌روزرسانی ساخت دوباره‌ی APK می‌خواهد؛ پیشنهاد نمی‌شود. iPhone: فقط وب (PWA) + خروجی تقویم.

## ۵) چیزهایی که بدون GitHub داخل خود برنامه انجام می‌شوند
Theme Studio (ساخت تم)، افزودن لینک منبع در آکادمی، وارد کردن بسته‌ی دوره، افزونه‌ها (فایل/لینک/متن) و بسته‌های جمله. هر چه فقط «محتوا» است را از هوش مصنوعی به‌صورت فایل قابل‌وارد‌کردن بخواه (کم‌خطرتر و کم‌حجم‌تر).

## ۶) به این چیزها توجه کن
- قبل از تغییر بزرگ: از داخل برنامه «پشتیبان کامل همه‌چیز» بگیر و zip مخزن را نگه دار.
- یک کار در هر نوبت؛ هر نوبت با zip **تازه**. وقتی چند هوش مصنوعی کار می‌کنند، فایل‌های تغییرکرده‌ی اولی را به دومی هم بده («این را هم ببین») و اگر پرسید «چیزی عوض شده؟» جواب بده، حتی اگر نه.
- فایل `index.html` و `sw.js` را با هر تحویل هم آپلود کن (شماره‌ی نسخه‌ی کش را بالا می‌برند)؛ وگرنه ممکن است تغییرها دیر برسند.
- از هوش مصنوعی «گزارش حجم قبل ← بعد» بخواه؛ بدون دلیل نباید بزرگ‌تر شود. کد را مینیفای نکن و عکس‌ها را دوباره فشرده نکن (به حد خود رسیده‌اند).
- در GitHub نام فایل‌ها را خودت عوض نکن؛ مسیر عکس‌ها داخل تم‌ها و داده‌ی تو ذخیره شده است.

## ۷) انتشار روی GitHub Pages و نصب از مرورگر
Settings ← Pages ← Source: Deploy from a branch ← `main` و `/ (root)` ← Save. بعد از یکی دو دقیقه سایت فعال است. نصب روی گوشی: Chrome ← ⋮ ← Add to Home screen. اجرای محلی روی کامپیوتر (نیاز به Python): `run-local.bat` یا `run-local.command` / `run-local.sh`.
